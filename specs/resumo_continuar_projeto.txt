============================================================
OBJETIVO PRINCIPAL
============================================================

Concluir a conversão integral do projeto legado Java + JNI + C para Go, preservando o comportamento funcional necessário para comunicação com pinpad ABECS físico por porta serial real.

O produto desta Change é uma biblioteca Go headless, sem HTTP, WebSocket, UI, daemon ou servidor externo. A implementação deve seguir o processo Spec Driven, possuir uma SPEC individual para cada comando com comportamento observável e ser validada funcionalmente com pinpad físico e porta serial real.

Objetivos ativos:

1. Concluir a conversão do legado Java + JNI + C para o módulo Go.
2. Manter rastreabilidade legado → Go → SPEC → teste → evidência física.
3. Implementar logging SPE/PP/RSP com redaction integral de dados sensíveis.
4. Implementar framing, CRC, retransmissão, fila, worker, cancelamento e shutdown conforme o manual ABECS.
5. Validar cada comando funcionalmente em hardware real, sem usar fake/mock como evidência final.

============================================================
PROTOCOLO ABECS
============================================================

Fonte normativa adotada:
  Pinpad ABECS — Protocolo de Comunicação e Funcionamento, versão 2.12, 11/abr/2019.

Parâmetros seriais:
  19.200 bps
  8 bits
  sem paridade
  1 stop bit

Controle e framing:

- SYN, ETB, DC3, ACK, NAK, EOT e CAN.
- CRC-16-CCITT.
- Payload original até 2049 bytes, conforme contrato documentado.
- Substitution de bytes de controle.
- Retransmissão máxima de 3 vezes, conforme confirmação do manual.
- Mensagens NTM.
- Comandos bloqueantes e não bloqueantes.
- Cancelamento por contexto e, quando exigido pelo fluxo, CAN/EOT.

O framing é transversal. Payload, status, resposta, timeout, redaction e validação devem ser definidos na SPEC individual de cada comando.

============================================================
LOGGING SPE/PP/RSP
============================================================

Implementar CommTracer na infraestrutura e injetá-lo no transporte/serviço sem acoplar o domínio ao slog.

- SPE: bytes enviados pela aplicação/SPE.
- PP: bytes recebidos do pinpad.
- RSP: correlação do comando e status após parse completo.
- Bytes em hexadecimal uppercase separados por espaço.
- SPE/PP devem registrar bytes observados mesmo quando a leitura ocorrer em chunks.
- STATUS deve permanecer em linha RSP separada.
- Redaction integral para GPN e GCX.
- Nunca registrar PAN, trilhas, PIN, PIN block, KSN, EMV sensível ou material criptográfico em claro.
- Não duplicar logs.
- Usar mutex para concorrência.
- Usar append mode.
- Destino vazio desabilita o logging.
- LogOpen e LogClose no adaptador serial.
- LogWrite, LogRead, LogRSP e LogIOError no fluxo de serviço/tracer.
- Erros devem preservar a causa Go com %w e registrar somente informação sanitizada.
